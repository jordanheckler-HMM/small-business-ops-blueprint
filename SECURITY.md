# Security and responsible reporting

This repository is a documentation project, not a place to store operational data or secrets. Read the [Privacy and safety guidance](docs/privacy-and-safety.md) before sharing material here.

## Do not disclose sensitive information

Do not put credentials, access tokens, customer/employee/business records, personal memory or transcripts, private profiles, machine-specific paths, or real operational data in public issues or contributions. Use synthetic data and placeholders instead. If sensitive information was posted accidentally, remove or restrict it where possible and rotate/revoke exposed credentials promptly; deleting a public post may not remove copies already made.

## Reporting a security concern

GitHub's repository setting currently reports private vulnerability reporting as disabled. Do not include sensitive details, exploit specifics, secrets, or real data in a public issue. Check the repository's current GitHub security settings before reporting, since settings can change. If no private reporting option is available, do not disclose sensitive details publicly. A public issue may be used only for a non-sensitive description or request for a private reporting route, without exploit details or confidential information.

This guidance does not replace the security policies of upstream projects. Report concerns about an upstream tool through that project's own official security channel.
