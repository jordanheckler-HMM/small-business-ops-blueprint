# Maintenance and support scope

This repository is a lightweight, docs-first blueprint. It is maintained separately from every upstream tool it mentions. The project maintainers can review this repository's wording, links, examples, and scope; they do not provide support, security response, compatibility guarantees, or release management for upstream projects.

## Keeping this guide useful

When making a documentation change or preparing a release, use a lightweight review:

- Check relevant upstream/source pages and record the date checked (`YYYY-MM-DD`) alongside claims that depend on them. Link to the authoritative source.
- Review documentation links and scan the affected pages for stale instructions, unsupported claims, privacy risks, and inconsistencies with the evidence labels.
- Before a release, review the documentation links and the full proposed change set; correct or clearly qualify anything that could not be confirmed.

This describes a review practice, not a fixed schedule or a promise of active monitoring. No claim is made that upstream changes are watched continuously. Users must verify current upstream versions, security guidance, data practices, and licensing directly before adopting or relying on a tool; projects and their terms can change at any time.

## Reporting documentation issues

For a non-sensitive correction or broken link, use the repository's public contribution process. Do not include credentials, personal information, private records, or exploit details in a public report. See [Privacy and safety](privacy-and-safety.md) and [Security and responsible reporting](../SECURITY.md) for boundaries and current reporting options.

This project does not promise ongoing maintenance, a response time, or support for a particular deployment. For a problem with an upstream tool, consult that project's official documentation and support or security channels.
